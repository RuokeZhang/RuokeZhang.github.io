项目总览

LinkedIn 通知系统的 Agentic RL,dual-agent 架构:

  • user agent:模拟真实用户对通知的反应(点没点、退没退订、有没有主动上 LinkedIn)。用 110K production member-day trajectories SFT Qwen3.5-4B,在 forward-in-time held-out set 上 <ORG:YES> 的 AUROC 达到 0.962。
  • rec agent:决定发不发、发什么(push/email/badge)、什么时候发(一天 6 个 4h 窗口)。SFT 之后用 GRPO 训练,以 user agent 作为环境,把模拟发送量削减 ~53%。
  • Scaling:SFT 栈从单卡 4B 扩到 16×H200 上跑 9B/27B,用多节点 FSDP/HSDP。

user agent 数据结构

一条 Avro record = (一个 member, 一天),展开成 6 个 SFT 样本(对应一天的 6 个 4h 窗口)。每个样本是一段 chat:

  • system = 固定的 SYSTEM_MODULE(说明输出协议)
  • user = context_module + memory_module + nextDayPrompt[i-1](第 2 个窗口起才有 ndp)
  • assistant = windowPrompt[i],里面内嵌了 <RES/ORG/QUAL> 答案

Special tokens 和 embedding resize

定义

RESPONSE_TOKENS = [
    "<RES:TAP>", "<RES:IGNORE>", "<RES:CLICK>",
    "<QUAL:UNSUB_EMAIL>",
    "<ORG:YES>", "<ORG:NONE>",
    "<QUAL:NONE>", "<QUAL:DISABLE_PUSH>",
]
SEGMENT_TOKENS = [
    "<email>", "</email>", "<push>", "</push>",
    "<badge_change>", "</badge_change>",
    "<organic>", "</organic>",
]

这些是项目自己发明的哨兵 token,任何预训练 tokenizer 都不会有。

为什么必须做成原子 token

如果直接扔给 BPE,<RES:TAP> 会被切成 <、RES、:、TAP、> 五段。带来两个致命问题:

  1. loss mask 会崩——一个决策要覆盖 5 个位置且顺序必须完全一致,还要跟前后 subword 边界对齐。
  2. eval 没法 exact match——AUROC 要在"决策位置的下一个 token 的 logits"上取 P(<ORG:YES>),必须是"一 token 一决策"才有得算。

所以流程是:

1
2

tokenizer.add_tokens(RESPONSE_TOKENS + SEGMENT_TOKENS)   # 16 个原子 token
model.resize_token_embeddings(len(tokenizer))             # embedding [N, d] → [N+16, d]

Warm start:避免开局 loss 爆炸

resize_token_embeddings 给新行的初值是"分布匹配但语义为 0"的随机向量。实测 step 1 loss 15.3 > ln(vocab)=11.9,grad-norm 187,前 ~150 步都在恢复而不是学习。

解决方案(train_sft.py:warm_start_new_token_embeddings):TOKEN_DESCRIPTORS 给每个新 token 配一句自然语言 gloss(比如 <RES:TAP> → "tapped the push notification"),用这句话被 tokenizer 切出来的 subword embedding 的均值作为新行的初值。

细节:k 个近似独立向量取均值会让模长缩水 ~√k,所以再把新行重缩放到已有 embedding 行模长的中位数——方向来自 gloss,尺度来自 backbone。tied embedding 直接 cover LM head,untied 时两处都要 seed。

两种打包模式:

  • --prefix_sharing chained:一条 record → 一个多轮 chat,cm+mm 只出现 1 次,后面 6 组 user(ndp delta) / assistant(wp[i])。长度差可达 1000×,配合 sequence packing 收益显著。

Label mask(项目关键设计)

sft_data.py:build_labels:

1
2
3
4

labels = [-100] * len(prefix_ids) + [
    tid if tid in response_ids else -100
    for tid in answer_ids
]

两层遮罩:

  1. prefix 全部 -100:system + context + memory + nextDay 完全不监督。特别是 SYSTEM_MODULE 说明书里出现的 <RES:TAP> 字面 token,如果不 mask,模型会学到"在说明书那个位置也能吐这些 token",污染分布。
  2. answer 内部只留 response_ids:助手回答里的格式脚手架也是 -100,只有 8 个 <RES/ORG/QUAL> token 有梯度。

prefix + answer 是一次性 tokenize(add_special_tokens=False),不是分两半——分两半会让 BPE 在边界合并出不一样的结果,监督位置会偏。answer_start 用字符 offset 反推。

为什么不用 TRL 的 SFTTrainer

TRL 的 SFTTrainer 只支持"一个 prompt → 一个 completion"。而这里:

  • 一段 answer 里有多处离散监督点(每个 intervention 的 response + window-end 的 organic/disable + email 的 unsub)
  • chained 模式一行有 6 个 assistant turn,每个 turn 内部又有多个监督点

用普通 transformers.Trainer + 自定义 collator 更干净。

Loss 内存栈(单卡 H200 装 4B 全量微调的关键)

技术干掉了什么开销
bf16param/grad/activation 减半
gradient checkpointing反向重算 activation
Flash / SDPA attention不物化 [seq, seq] 注意力矩阵
Liger 融合 linear+CE不物化 [seq, vocab] logits(~30GB 尖峰),自动跳过 -100 位置

Liger 那条最关键:标准做 LM loss 会短暂占用 [batch, seq, vocab≈150k] 的 logits 张量(几十 GB)。Liger 把 linear → CE 融合成一个 kernel,logits 从来不作为完整张量存在。

分布式策略(--dist_strategy)

  • DDP:模型能放进单卡时最快(4B on H200)。只在梯度更新时 all-reduce 一次。
  • FSDP full_shard:参数/梯度/优化器状态跨 rank 分片。单卡装不下时用(9B/27B)。每层 forward 前 all-gather,通信量大。
  • HSDP:节点内 FSDP + 节点间 replicate。参数 all-gather 走 NVLink,梯度同步跨节点走 IB。多节点 scale 到 16 卡时启用。

踩坑:数据层不做 rank sharding(shard_in_data_layer=False),让 accelerate 做统一分片,否则 IterableDataset 会被双重分片,静默丢数据。

Eval(0.962 AUROC 出自这里)

  • In-loop AUROC:每 eval_interval_frac × max_steps 步跑一次。teacher-forced,在 <ORG:YES>/<ORG:NONE> 的决策位取 softmax(logits)[<ORG:YES>_id] 作为 P(organic),对 held-out 集合算 AUROC。
  • Final eval:训练结束跑 100k items(可配)的 held-out。
  • Held-out 是时间上"未来"的分区——不是随机切,eval_data_dir 指向后续日期的 Avro 分区,防止时间穿越。0.962 是 forward-in-time 的数字。

常见追问

Q: 为什么不用 JSON 输出? JSON key 会被 BPE 切碎,mask 和 eval 都难对齐;原子 token 保证"一 token 一决策",AUROC 直接在那一位算。

Q: warm start 有实测收益吗? 有。不做的话 step 1 loss > ln(vocab),前 ~150 步在恢复而不是学习。

Q: LM head 也要 resize 吗? 要。tied embedding 时同一存储直接 cover;untied 时 embedding 和 head 都要单独 seed。

Q: 为什么不用 TRL SFTTrainer? 它只支持单一 prompt→completion 分割。这里 answer 内部有多处离散监督点,需要自定义 token-level label mask。

  • bf16 → 是 memory-bound 优化：省参数/梯度/激活显存

  • fp8 → 主要是 compute-bound 优化：加速矩阵乘法（GEMM）

    在一个 transformer 层里，只有特定几个大 Linear 被换成 Float8Linear：

  • Attention 里：q_proj / k_proj / v_proj / o_proj

  • FFN 里：gate_proj / up_proj / down_proj
