左值右值

  • 左值：可以取地址的对象

    • int a=5 中的 a
    • ++i （这是一个对象）

  • 右值：表达式结束后销毁的临时对象。

    • int a=5 中的 5
    • i++（返回自增前的临时值）
    • 纯右值（prvalue）：字面量，临时对象
    • 将亡值（xvalue）：通过 std::move 转换后的对象（即将被销毁，可被 “移动” 资源的对象）

  • std::move 用于完成移动构造。移动构造避免不必要的拷贝，提高性能

failure

During a big promotion our model’s TPM (500,000 tokens/min) was exhausted and many highlight requests started failing. My goal was to stabilize the service quickly without just dropping requests. I added a worker-side token bucket (Redis) so a task only calls the model if tokens are available, otherwise it gets delayed and retried later. I also tied autoscaling to token usage and queue length so we automatically add capacity when pressure rises. Within minutes the failure rate fell below 1% and the task queue stopped growing.

Lecture 6

Word Embeddings & X2Vec

Word2Vec

  • Skip-Gram， semi-supervised
  • 生成训练数据：通过移动窗口扫描句子，生成 (输入词, 目标词) 对
  • 架构：input(one-hot), 1 hidden layer, softmax classifier

Product2Vec (X2Vec)

  • View Similarity：学习 Substitutability（可替代性/严格相似）
  • Purchase Similarity：学习 Complementarity（互补性/搭配关系）

BERT

  • bert base: 12 layers of encoder
  • [CLS]：放在句首，用于整个句子的分类表示。
  • [SEP]：放在句尾或两句之间，作为分隔符。
  1. normalization： all lower case
  2. WordPiece Tokenization
  3. add special tokens: [CLS]/[SEP]
  4. Token IDs(BERT vocab)
  5. each token got 3 embeddings，sum them up
    • token embedding(get from a huge matrix, size of [Vocab_Size, 768])
    • position embedding(get from a matrix, size of [Max_Len, 768])
    • segment embedding
  6. got a matrix[token_size*768]
  7. pass the matrix through a 12 Encoder Layers. After that, [CLS] would gather information from the entire sentence

Candidate Part

  • First, we aggregate the livestream into minute-level metrics, including normalized signals like watch PV, user actions, and order creation.
  • Then, instead of using a single metric, we combine them into a composite score and apply a 5-minute rolling z-score to detect spikes relative to the recent baseline. This helps us identify highlight moments in a way that adapts to different livestream dynamics.
  • for each peak, we calulate a contribution score, means how much a metric contribute to the composite score, and assign a tag to a peak. for example, a peak may have “engagement-driven” or “conversion drivien” tag
  • For each peak, we verify whether the previous minute shows a similar pattern,
  • Finally, we expand each detected peak into a candidate window. The expansion strategy depends on the tag—for example, traffic-driven highlights require more context, so we expand further, while conversion-driven highlights tend to be more localized.
