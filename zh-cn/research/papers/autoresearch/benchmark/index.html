MLE-Dojo Benchmark

这是什么

MLE-Dojo 是一个面向 LLM machine learning engineering（MLE）agent 的交互式 benchmark / Gym-style 环境。它把真实 Kaggle 竞赛整理成可执行任务，让 agent 不只是回答问题，而是要反复读数据、写代码、运行实验、根据反馈调试，并提交预测结果。

论文版本的数据集包含 200 多个 Kaggle 任务；实验从中选取 50 个任务评测模型。任务覆盖 Tabular、NLP、Computer Vision 等类别，数据集也可扩展到时间序列等任务。它的重点是评估完整的迭代式 ML 工作流，而不是单次代码生成。

理解任务与 metric
  → 检查数据和文件
  → 设计预处理、特征和模型
  → 编写并运行训练代码
  → 在 validation 上评估
  → 根据分数或报错修改方案
  → 生成符合格式的 test predictions / submission

环境会执行 agent 提交的代码并验证结果，因此代码能否运行、输出格式是否正确，以及模型效果如何，都会影响最终表现。实验允许多次尝试，关键能力包括数据处理、模型选择、调参、错误诊断和持续改进。

NLP：文本任务

文本任务可能是分类、毒性检测、作者识别、语义相似度或文本规范化。例如 MLE-Dojo 收录的 random-acts-of-pizza 任务，要求根据 Reddit 用户的求助文字，预测其最终是否收到 pizza；这是一个以 AUC 评估的二分类任务。

Agent 可以从 TF-IDF + Logistic Regression 等传统方法开始，也可以尝试预训练模型的 embedding 或微调，并用 validation 结果比较和迭代方案。

怎么评估

  • HumanRank（H-Rank）：衡量 agent 在对应 Kaggle leaderboard 上超过了多少比例的人类参赛者，范围为 0–1（展示时也可写成百分比）。论文分别计算 public 和 private leaderboard 上的相对成绩，再取平均作为最终 reward。它将不同竞赛的原始 metric 映射到可比较的相对表现。
  • AUP（Area Under the Performance Profile）：概括模型在不同性能阈值下、跨任务表现的稳健性；越高通常代表在更多任务/阈值上维持较好的相对性能。
  • Elo：通过模型之间的相对表现做成对比较，形成排序分数。

因此，HumanRank 更直观地回答“相对人类做得怎样”，AUP 看跨任务表现分布与稳定性，Elo 则反映模型间的相对胜负关系。论文会结合这些指标，而不是只看某一个竞赛的原始分数。

阅读时可以关注

  • 交互式而非一次性：agent 可以运行、观察反馈，再修改方案；benchmark 考察的是迭代解决问题的能力。
  • 结果可验证：实际执行和评测代码，减少只凭文字判断答案质量的问题。
  • 任务异质性强：不同竞赛的数据、metric 和提交格式不同，agent 需要先读懂任务，而不能依赖固定模板。
  • HumanRank 是相对指标：它便于跨任务比较，但表示的是相对人类 leaderboard 的位置，不等同于统一的业务效用或绝对模型质量。
