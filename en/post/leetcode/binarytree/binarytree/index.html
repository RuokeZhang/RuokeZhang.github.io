Binary Tree Patterns

February 12, 2025

Problem list

Bottom-Up DFS: Postorder Traversal

Use postorder when the computation at a node needs results from its children.

  • 1110, Delete Nodes and Return Forest: Process children before deciding which remaining subtrees become new roots.
  • 1123, Lowest Common Ancestor of Deepest Leaves: Return both the deepest depth beneath a node and the common ancestor of leaves at that depth.
  • 1530, Number of Good Leaf Nodes Pairs: Return the distances from a node to leaves in its subtree. Combine distances from opposite children to count valid pairs.

Preorder Traversal

1026, Maximum Difference Between Node and Ancestor: Carry the smallest and largest ancestor values down the path. A postorder solution is also possible.

Constructing a Binary Search Tree

For a sorted array, choose its middle element as the root and recursively build the left and right subtrees. This pattern appears in problems 108, 109, and 1382.

With a sorted linked list, random access to the middle is inconvenient. Instead, construct the tree in inorder: build the left subtree, use the current list node as the root, advance the list pointer, and build the right subtree. The traversal order consumes the sorted values in exactly the order needed.

Trees and Linked Lists

Linked-list or pointer techniques can reduce auxiliary space:

  • 117, Populating Next Right Pointers in Each Node II: Traverse one level through next pointers while linking the next level, without a queue.
  • 109, Convert Sorted List to Binary Search Tree: Consume the list during inorder construction.

Diameter and Tree Dynamic Programming

For many tree-path problems, DFS returns the best path that can be extended through the parent and updates a separate answer using paths from both children.

  • 543, Diameter of Binary Tree: Combine the depths of the left and right subtrees at each node.
  • 687, Longest Univalue Path: Extend only through child edges with matching values.
  • 124, Binary Tree Maximum Path Sum: A path used by the parent can follow at most one child; the answer at a node may join both sides.
  • 549, Binary Tree Longest Consecutive Sequence II: Track increasing and decreasing paths separately and combine them at a node.

2385, Amount of Time for Binary Tree to Be Infected

One approach is to treat parent and child links as undirected edges and search outward from the start node. Another DFS approach tracks whether a subtree contains the start node and how far its deepest leaf is. When combining two children, only paths that pass through the infected node contribute to the infection time.

Breadth-First Search

863, All Nodes Distance K in Binary Tree: First record each node’s parent, then run BFS from the target over left, right, and parent neighbors. Keep a visited set to avoid walking back and forth.

Other Binary Tree Problems

666, Path Sum IV: The encoded position of a node identifies its parent and children, so a separate tree object is unnecessary. Carry the path sum from root to leaf and add it to the answer at each leaf.

General Trees

In a tree, the path between any two nodes is unique. For an undirected representation, pass the parent into DFS so traversal does not immediately return along the incoming edge. DFS can start at any node.

  • 1466, Reorder Routes to Make All Paths Lead to the City Zero: Traverse the undirected tree from city 0 and count edges whose original direction points away from it.
  • 1376, Time Needed to Inform All Employees: Memoize the time needed to reach an employee through their manager chain. Once computed, mark the chain as processed so later calls reuse the result.
  • 834, Sum of Distances in Tree: First DFS computes each subtree’s size and the sum of depths from an initial root. A second DFS reroots the answer across each edge: answer[child] = answer[parent] + node_count - 2 * subtree_size[child].

Traversal and Binary Search Trees

Remember preorder, inorder, and postorder, including iterative traversal with a stack. A BST’s preorder sequence can reconstruct a unique BST using recursion with bounds or a monotonic stack; see problem 449.

For 173, Binary Search Tree Iterator, push the root and all its left descendants onto a stack. The top is the smallest unvisited node. After popping it, push its right child and that child’s entire left chain. Each node is pushed once, and the stack uses O(h) space for tree height h.

When to Add Parent Links

Build a parent map when a process can spread upward as well as downward, or when the starting point is an arbitrary node rather than the root. Problems involving infection, fire, or nodes at distance K often have this shape. For problem 2385, find the start node while building the map, then traverse left, right, and parent links from it, tracking visited nodes.
